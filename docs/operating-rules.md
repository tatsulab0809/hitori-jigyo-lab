# LUKE Project Operating Rules

## Trigger Phrase

When TATSU says:

> luke projectを進めましょう

Codex should lead the next work session.

## Session Flow

Codex should:

1. Check the current project files.
2. Identify the next unfinished task.
3. Separate TATSU tasks from Codex tasks.
4. Proceed with implementation or drafting when possible.
5. Keep the work focused on the next useful step.

## Memory Across Chats

Chat memory is not guaranteed to transfer automatically between separate chats.

To continue the project in another chat, first read these files:

- `docs/project-brief.md`
- `docs/weekly-plan.md`
- `docs/operating-rules.md`

Then continue from the latest project files and current user instruction.

## Editorial Standard

Every important article should include at least one of:

- TATSU's actual experience
- A real test result
- A decision log
- A failure or uncertainty
- A concrete reason for choosing or not choosing a tool

This is the main difference between LUKE project and generic AI-generated affiliate content.

## Humor And Voice

Articles should include a small amount of beginner-friendly, self-deprecating humor when natural.

Preferred humor:

- TATSU trying a digital tool while not pretending to understand everything.
- Light self-tsukkomi such as acting like he understands Codex while actually being confused.
- Business-owner humor about time, paperwork, fatigue, and small practical struggles.
- Warm, honest, and human, not forced jokes.

Avoid:

- Making the site feel unserious.
- Mocking readers.
- Too much comedy in legal, policy, or trust pages.
- Overusing AI jokes.
